0 这是什么：一个场景

一位生物学家在 96 孔板里培养脑类器官，一半孔加了候选药物，一半是对照组，第 5、10、15 天各在显微镜下拍一遍明场照片，几百张图，每张几十个类器官。她想知道加药组是不是长得更慢、形态是否变得不规则、差异在统计上是否成立。今天的做法是在 ImageJ 里逐个手工圈出类器官量面积，再导到表格里算，一整天耗在这上面，而且换个人圈结果就不一样。

用 Orgalyst，她把图片文件夹拖进网页，输入一句"比较加药组和对照组在三个时间点的大小和形态差异，给我一份报告"。系统随后自动完成五步：用分割模型圈出每张图里的每个类器官；对每个类器官测量面积、直径、圆度等十几项指标；检查失焦的图和贴边的实例并标记为低可信；按组和时间点做统计检验、画生长曲线；生成一份网页报告，含图表、数值、方法学说明，末尾附上所用模型版本、参数和每张输入图的校验值。整个过程几分钟。她还能追问"第 15 天的差异是不是由几个特别大的类器官造成的"，系统会回到数据里回答。

拆开看，项目由三部分组成。一是几个训练好的图像模型，负责在类器官照片里找到并圈出每个类器官，这是我们在 OrgLine 数据上训练和评测的部分，也是技术报告里实验结果的主体。二是一个分析工具包，负责测量、质控、统计和报告生成，全是确定性代码，不涉及大模型。三是一个对话式助手，在 bioagent 基础上改造，负责理解用户要求、按顺序调用前两部分、用人话解释结果。大模型只做第三部分，它不看图也不算数，所以结论不会被它编造。

它不涉及湿实验，不需要新的显微镜或芯片硬件，也不是通用聊天机器人。它是实验拍完照之后那一段数据分析工作的自动化。比赛要交的是这套软件的代码仓库、模型权重、说明方法与效果的技术报告，以及五分钟的操作演示视频。

1 定位与目标

器官芯片和类器官实验产出的主要数据是明场显微图像，但把图像变成"这一组类器官比对照组小了多少、形态是否异常、结论可不可信"这样的定量结论，目前仍依赖人工圈画或需要会写代码的分析人员。Orgalyst 要解决的就是这最后一公里：研究者用一句话提出问题，系统自动完成类器官检测与分割、形态定量、质量控制、组间比较和报告生成，并把每一步的模型版本、参数和中间结果留档，让结论可以追溯和复现。

项目建立在两块已有工作之上。第一块是 bioagent，一个基于 Claude Agent SDK 的终端与网页版生物医学助理，已经具备会话管理、权限控制、长期记忆、工具按需加载和 223 个生信工具的 MCP 接入。第二块是类器官分割的技术选型与 cyto3 微调框架，之前在公司项目里做过零样本横评，框架代码可以直接复用，数据则全部换成公开的 OrgLine。本项目的新增工作集中在一个领域工具包 orgatools、对应的 MCP 服务器、面向 OrgLine 的模型训练与评测，以及把这些串成可演示的端到端流程。

一句话价值主张。让不写代码的生物学家在五分钟内完成一次类器官形态学分析并拿到一份带证据链的报告，而不是等一周排队找分析人员。

3 系统架构

系统分四层。最上面是交互层，复用 bioagent 的网页版和终端版；中间是编排层，由 Agent 根据用户意图调用工具并维护会话与留档；再下面是领域工具层，也就是本项目新写的 orgatools，通过 MCP 暴露给 Agent，同时提供独立命令行；最下面是模型与数据层。

关键设计决定有三条。第一，orgatools 是一个普通 Python 包，先有命令行入口再包 MCP，这样评审不装 Agent 也能复现全部定量结果。第二，Agent 不做"看图"，所有图像理解都由领域模型完成，大模型只负责理解意图、选择工具、解释结果和写报告，这样结论不会被大模型幻觉污染，也便于换成开源模型。第三，每次分析生成一个带哈希的 run 目录，记录输入文件校验和、模型版本、参数和输出，报告末尾自动附上，这就是"可追溯"的具体实现。

6 实验设计

五组实验对应评分里的"结果与验证"和"技术创新"，E1 到 E3 是报告的主体，E4 和 E5 是差异化。所有实验的配置文件和结果表都进仓库。

E1 实例分割（P0）

在 InstanceSeg 四种器官的官方划分上评测。指标为掩码 AP50、AP50:95、IoU 0.5 下的 F1，以及每图计数误差。对比的模型有：cyto3 零样本，cpsam 零样本，cyto3 按器官微调，cyto3 跨器官联合微调，YOLO11-seg。额外做一组留一器官（leave-one-organ-out）实验来回答"跨器官模型能否泛化到没见过的器官"，这是审稿人和评委都会问的问题。OrgLine 论文报告的数值作为外部参照写进表格。

E2 检测与计数（P0）

在 OrgDet 三种器官上训练 YOLO11，报告 mAP50、mAP50:95 和计数的 MAE 与 MAPE，按器官分别给出。同时比较"按器官单独训练"与"三器官联合训练"。

E3 形态学与人工测量的一致性（P0）

用脑类器官原始数据集自带的人工尺寸作为参照，计算自动测量与人工测量的 Pearson/Spearman 相关、Bland-Altman 一致性界限，并按四个克隆分别画出 5 到 30 天的生长曲线，检验健康克隆与疾病克隆的差异是否能被自动流程复现。肠类器官则比较健康与囊性纤维化两组的圆度和面积分布，对应 OrgaSegment 论文里的肿胀实验。

E4 质量控制与不确定性（P1）

验证 QC 分数的有用性：失焦分数与分割误差的相关性；TTA 一致性得分能否把错误分割的实例排在前面（以 AUROC 报告）。再做一个消融，说明在报告中标出低置信实例后，人工复核的工作量下降多少。

E5 Agent 端到端任务集（P1）

设计 12 个自然语言任务，覆盖单图分析、批量分析、组间比较、生长曲线、生成报告和追问解释，每个任务定义可自动判定的成功标准（比如输出文件存在且数值在容差内）。报告成功率、平均工具调用次数、平均耗时，并分别在 Claude 与本地开源模型两个后端上跑，如实给出差距。

E6 剂量响应（P2，视时间）

在 BBBC021 上以形态学指标拟合 4PL 曲线，与已知作用机制标签做一致性检查。若第三周仍未开始，直接放弃并在报告的"局限与未来工作"里说明。

7 可复现性方案

评审要在没有付费服务的前提下复现。因此仓库提供两条路径：命令行路径不需要任何大模型，能复现报告里的全部数值；Agent 路径默认用 Claude，同时给出本地开源模型的配置。

12 已定事项与默认取舍

以下决定已经做出，后续按此执行；最后两项是默认取舍，若中途改变主意在第二周末前告知即可。

  1. 项目名 Orgalyst。organoid 与 analyst 的合成词，读作 or-ga-lyst，GitHub 与 PyPI 均无同名项目。仓库名 orgalyst，Python 包名 orgalyst（领域工具子包 orgalyst.tools），Hugging Face 权重前缀 XiaoyanLi/orgalyst-。
  2. 团队。已邀请一位生物学同事入队，团队构成为 AI 加生物学，报告中声明以获得学科交叉加分。
  3. 分割主模型 Cellpose cyto3 微调。依据是此前零样本横评的结果，并且微调框架已有。YOLO11-seg 仅作为 E1 的对比基线，不作主模型。
  4. 默认使用按器官的专用权重。即使 E1 显示跨器官通用模型与专用模型差距不大，系统仍默认按用户声明的器官类型加载对应的专用权重；跨器官模型只用于实验对照，以及用户处理五种器官之外的新类型时的兜底。器官类型来自实验设计表，不由模型从图像猜测。
  5. 开源模型替代路径保持 P1。可复现性的硬要求由无大模型的命令行路径满足，开源模型路径是加分项，排在 qc 与 compare 之后。
  6. BBBC021 剂量响应保持 P2。默认不做，报告中写入未来工作。
