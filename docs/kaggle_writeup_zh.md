## 一句话

实验人员对着助手说一句“分析这批肠类器官照片，比较两组面积，给我一份报告”，几分钟后拿到一份可以放进实验记录、三个月后仍能复核的分析报告；报告里的每一个数字都能在没有任何大模型的环境下用命令行重新算出来。

## 解决什么问题

类器官和器官芯片实验每天产生大量明场显微照片，最常问的三件事是“有几个、多大、有没有变化”。现有工具要么是需要装环境、调直径参数的脚本，要么只做分割、不管后面的测量、统计和留档，把一批图变成一份报告仍然要花半天，而且三个月后没人说得清“这个面积是用哪个模型、什么参数算出来的”。

## 做了什么

系统分两层。

**工具包 `orgalyst`（确定性，不需要大模型）**
- 按器官加载专用的 Cellpose 分割权重（cyto3 在 OrgLine 上按脑、肠、胰腺癌、结肠分别微调），并为每种器官选择直径策略（模型直径 / 逐图尺寸估计 / 两遍推理），解决 Cellpose 在类器官上最常见的尺度失败。
- 三器官联合的 YOLO11m 检测模型只负责“数有几个”，计数阈值在验证集上标定，而不是用默认值。
- 形态测量（面积、等效直径、周长、圆度、实心度、长宽比、贴边标记，给像素尺寸则换算微米）、两级质控（图像级清晰度 / 光照 / 饱和；实例级翻转旋转一致性，标出不可靠的分割）、组间统计（Mann-Whitney / Kruskal、Cliff's delta、Holm）、生长曲线。
- 单文件 HTML 报告，和记录输入 md5、权重哈希、参数、软件版本的运行清单，任何人可复现。

**对话式助手（Claude Agent SDK + MCP）**
- 工具包通过 MCP 暴露六个工具；助手负责理解需求、选器官权重、传参数、核对结果、解释，不看图、不算数。
- 分析规程写成 skill：先确认器官、像素尺寸和目的，再选工具，拿到结果先核对（离群计数看叠加图，贴边排除和低可信数必须写进回答），最后按固定格式汇报；没有像素尺寸时绝不给微米数字。
- 终端版和网页版（多账号、权限门卫、用量上限），也支持指向开源模型网关。

## 结果（OrgLine 测试集）

| 实验 | 结果 |
|---|---|
| E1 分割 AP50（零样本 cyto3 → 按器官微调 + 直径策略） | 脑 0.005 → 0.967；肠 0.544 → 0.812；结肠 0.405 → 0.815；胰腺癌 0.419 → 0.591 |
| E1 跨器官 | 留一器官模型在未见器官上仅 0.15–0.47，专用权重是必要的；Cellpose-SAM 微调后与 cyto3 微调持平，权重大 50 倍，不采用 |
| E2 检测计数（YOLO11m 联合模型） | mAP50 肠 0.948 / 脑 0.995 / 肺 0.936；阈值标定后计数误差肠 0.262 → 0.207、肺 0.235 → 0.168 |
| E3 与专家标注一致性（脑，240 图） | Spearman 0.963，中位相对误差 1.9%，93% 的图误差 ≤ 10% |
| E4 质控 | 被标为“低可信”的实例中错误实例占比是其余实例的 3.5–6.8 倍（作为提示而非过滤） |
| E5 Agent 端到端任务集（12 个自然语言任务，自动判定） | 12/12 通过，平均 113 秒、10.5 次工具调用，合计 5.6 美元 |

## 如实说明的局限

胰腺癌类器官上召回只有约一半（测试图实例密度是训练图的七倍、仪器不同）；只有脑数据集有像素标定，其余器官只报像素；Agent 路径只在 Claude 一个后端上评测，依赖付费 API；命令行路径不受此限制，报告里的全部数字都可由它复现。

## 复现

`pip install -r requirements.txt` → `bash scripts/download_weights.sh` → `python -m orgalyst analyze --organ intestine --images DIR --out runs`。复现全部表格的脚本顺序与预期耗时见 README 与技术报告第 10 节；仓库已含我们跑出的全部结果文件。Docker 镜像覆盖命令行路径。
