## 1 要解决的问题

类器官是用干细胞在三维环境里培养出的微型组织，器官芯片把这类组织放进微流控器件里模拟生理条件。无论哪一种，最便宜、最不伤细胞、频率最高的观察手段都是明场显微镜：每天或每隔几小时拍一张，看它们长得怎么样。这些照片的分析需求非常固定：数清楚一张图里有多少个类器官，量出每个的大小和形状，比较不同处理组之间有没有差异，把同一个类器官在不同时间点的测量连成生长曲线，最后写成能放进实验记录、能被别人复核的报告。

瓶颈不在算法。Cellpose、OrganoID、OrgaSegment 已经能把类器官分割得相当好，OrgLine 数据集还把八个公开来源整理成了统一格式。真正卡住实验人员的是三件事：工具是给会写代码的人用的，要装环境、选模型、调直径参数，一张图上类器官大小相差十倍时默认参数会失效；分割只是第一步，后面的测量、统计、画图、写报告每个实验室都在重复造轮子，做法不一致，结果没法横向比较；没有留档，三个月后审稿人问“这个面积是用哪个版本的模型、什么参数算出来的”，多数人答不上来。

Orgalyst 的目标用户是做类器官或器官芯片实验、不写代码的生物学研究者。我们给自己定的成功标准有三条：用自然语言就能拿到完整的分析报告；报告里的每个数字都能用命令行在没有大模型的环境下重新算出来，并且和公开数据集自带的专家标注一致；系统对自己不确定的地方要说出来，而不是给一个看起来很准的错误数字。

## 2 系统是什么

系统分两层。**工具包层** `orgalyst` 是一个普通的 Python 包，命令行入口 `python -m orgalyst analyze | count | track | report`，不需要任何大模型；每次运行都在一个目录里留下 `manifest.json`（输入文件的 md5、模型标识与权重哈希、全部参数、软件版本、GPU 型号、逐步日志）、逐实例特征表、汇总、质控与比较表、掩码、叠加图和一份单文件 `report.html`。**助手层**基于 Claude Agent SDK，工具包通过一个 MCP 服务器暴露六个工具（列模型、分析、计数、组间比较、生长曲线、回看运行），助手负责理解需求、选器官权重、传参数、核对结果、解释；它不看图、不算数。

### 2.1 工具包做了什么

**分割。**用 Cellpose（U-Net 回归流场，像素沿流场汇聚成实例），但不用它的通用权重直接推理，而是把 cyto3 在 OrgLine 上按脑、肠、胰腺癌、结肠分别继续训练 200 轮，得到四套专用权重；并为每种器官选定直径策略：结肠用权重里记住的训练直径，肠和胰腺癌用尺寸估计器逐图估计，脑用两遍推理（第二遍用第一遍找到目标的中位直径）。Cellpose 在类器官上最常见的失败是尺度估错，通用模型对 400 像素宽的脑类器官会估成 30 像素，零样本 AP50 只有 0.005；专用权重把尺度记住了，两遍推理又解决了脑类器官从第 2 天到第 30 天面积变化近五倍的问题。不认识的器官退回通用模型，并在报告里标注“精度较低”。

**计数。**用户只问“有几个”时分割是浪费的，一个三器官联合训练的 YOLO11m 检测模型在不到一秒内给出数量；计数用的置信度阈值不是默认的 0.25，而是在各器官验证集上按计数误差最小标定（肠 0.50、脑 0.45、肺 0.40）。

**测量、质控、统计、生长曲线。**测量给出面积、等效直径、周长、圆度、实心度、长宽比和是否贴边，给了像素尺寸就同时输出微米列，贴边的不完整实例默认排除并说明数量。质控分两级：图像级算清晰度、光照不均和饱和比例；实例级做翻转旋转的测试时增强，一个实例在变换后被找回的比例低于一半就标为“低可信”，报告里用橙色标出。组间比较用 Mann-Whitney 或 Kruskal-Wallis，报告 Cliff's delta 效应量，多指标 Holm 校正；生长曲线按个体、时间点、组把逐图中位面积连起来，给出相对第一个时间点的倍数。

### 2.2 助手怎么工作

光有工具还不够，助手在什么情况下该问什么、先跑什么、怎么核对、怎么汇报，我们写成了一个 skill（`agent/skillpack/skills/organoid-analysis`），用户提到类器官图片分析时自动生效。它规定四步：先确认三个前提（器官类型、像素尺寸、要数量还是形态还是比较，缺哪个问哪个，但不为简单任务阻塞）；按前提选工具（只数数走检测，其余走分割，图片少或用户关心可靠性时开质控，有分组或时间点信息时接统计）；拿到返回先核对（逐图计数出现 0 或离群值就去看叠加图，贴边排除数和低可信数必须写进回答）；最后按固定的六段格式汇报。skill 同时列出禁止事项：没有像素尺寸时不给任何微米数字，不用 Python 重算工具已经给出的统计量，不重复跑同一批图。

| 用户会怎么问 | 助手做什么 | 用户得到什么 |
|---|---|---|
| “这批图里有几个类器官？” | 检测模型逐图计数，阈值取标定值 | 逐图数量表、画了框的图 |
| “分析这批肠类器官照片，告诉我大小和形状” | 专用权重分割 + 测量 + 报告 | 总数、逐图表、面积 / 直径 / 圆度的中位数与四分位范围、report.html |
| “像素尺寸是 3.16 µm，面积换成平方微米” | 把标定传给工具 | 微米单位的结果；没给标定时明确说“只报像素” |
| “哪些分割结果靠不住？” | 开启两级质控 | 图像质量指标、橙色标出的低可信实例 |
| “对照组和处理组的面积有没有差异？” | 按分组文件做检验与效应量 | 各组中位数、p 值、Cliff's delta、箱线图，结论说人话 |
| “从第 2 天到第 30 天长了多少？” | 按个体与时间点连生长曲线 | 首末时间点数值与倍数、按组均值曲线 |
| “这次用了什么模型、参数？以后怎么复现？” | 读运行清单 | manifest.json 路径及其记录的哈希、参数、版本 |
| “分析 /data/x 里的图”（空目录 / 器官没说） | 说明没找到图片；或用通用模型并声明精度较低 | 一句明确的说明，而不是一个看起来正常的数字 |

## 3 结果

五组实验全部在 OrgLine 的测试集上完成，指标为实例级 AP50（预测与真值 IoU ≥ 0.5 记为匹配）等。

| E1 分割 AP50 | cyto3 零样本 | 按器官微调 | 微调 + 逐图直径策略（系统默认） | 真值直径（上限） |
|---|---|---|---|---|
| brain (240) | 0.005 | 0.925 | **0.967** | 0.975 |
| intestine (12) | 0.544 | 0.773 | **0.812** | 0.812 |
| colon (10) | 0.405 | **0.815** | 0.814 | 0.800 |
| pdac (20) | 0.419 | 0.564 | **0.591** | 0.605 |

三点结论：零样本 cyto3 认得类器官但过度分割严重，微调解决了尺度与边界两个问题；直径策略的收益是真实的（脑 0.925 → 0.967，肠 0.773 → 0.812）；胰腺癌仍然弱，测试图每张 500 个以上小实例、来自另一台仪器，召回只有约一半。留一器官实验表明跨器官泛化有限（未见器官 0.15 到 0.47），专用权重是必要的；Cellpose-SAM 微调后与 cyto3 微调持平（胰腺癌 0.557、肠 0.780），权重大 50 倍、推理慢一倍，只作对照。

| E2 检测计数（YOLO11m 联合模型） | mAP50 | 标定阈值 | 计数 MAPE（默认 0.25 → 标定） | 中位相对误差 |
|---|---|---|---|---|
| intestine (423) | 0.948 | 0.5 | 0.262 → 0.207 | 0.13 |
| brain (280) | 0.995 | 0.45 | 0.018 → 0.004 | 0.00 |
| lung (602) | 0.936 | 0.4 | 0.235 → 0.168 | 0.11 |

**E3 与专家标注的一致性**（脑，240 张，自动面积 vs 原始数据集的人工面积）：检出 237 / 漏检 3，Spearman 0.963，中位相对误差 1.9%，93% 的图误差 ≤ 10%。**E4 质控**（肠、结肠、胰腺癌测试集）：被标为低可信的实例中错误实例（IoU < 0.5）的占比是其余实例的 3.5 到 6.8 倍，但召回率只有 0.07 到 0.13，所以报告把它定位为“提示”而不是“过滤”。

## 4 可复现性

仓库提供两条路径。**命令行路径**不需要任何大模型：`pip install -r requirements.txt`，`bash scripts/download_weights.sh`（权重约 200 MB，国内加 `--mirror`），然后 `python -m orgalyst analyze --organ intestine --images DIR --out runs` 即可对任意一批明场图出报告；复现报告里全部表格的脚本顺序与预期耗时（数据准备 15 分钟、E1 微调 2.5 小时、跨器官 3 小时、E2 检测 4.5 小时、E3 10 分钟、E5 25 分钟）写在 README 和技术报告第 10 节，仓库已包含我们跑出的全部结果文件，Dockerfile 覆盖这条路径。**Agent 路径**默认用 Claude API（需要评审自己的密钥），也可以通过 `ANTHROPIC_BASE_URL` 指向兼容 Anthropic 接口的开源模型网关；`agent/` 目录是助手的完整代码，不含任何账号与密钥。

## 5 局限

胰腺癌类器官的召回只有约一半，需要更多同源数据或针对小实例的多尺度推理；只有脑数据集有像素标定，其余器官只能以像素为单位；肠（12 张）和结肠（10 张）测试集很小，AP50 的置信区间宽；Agent 路径只在 Claude 一个后端上评测，12 个任务也不能覆盖真实使用里的全部问法；助手曾在工具失败时自己写分割代码“补救”，我们已在权限门卫加入硬性拦截并完整复跑了任务集；数据全部来自已发表的公开数据集，没有器官芯片的时序数据。这些都在技术报告第 8 节展开。

## 6 影响与下一步

对实验人员而言，从拍完照片到拿到报告从半天缩短到几分钟，而且报告可复核；对方法研究者而言，加一个器官只需要一份权重和一行配置。下一步最有价值的三件事：器官芯片上位置固定的类器官可以把检测框在时间上关联做逐个体追踪；在形态学指标上拟合剂量响应曲线；把助手接到成像系统的调度接口，让“拍完自动分析、异常时提醒”闭环起来。
